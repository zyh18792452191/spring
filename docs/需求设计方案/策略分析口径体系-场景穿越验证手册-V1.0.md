## 一、口径体系总览

### 1.1 策略分析的业务定位
策略分析是评估中心下的策略派发效果评估页面，统计所有关联了策略的工单（排除指标调度IND）的派发行为和执行效果。

### 1.2 口径维度定义（2维度×4种口径）
- 范围：本级 / 全口径
- 时间：当月 / 累计
- 无视角维度（策略分析只有派发视角，不设接单视角）

### 1.3 统计范围
所有strategyId非空且ticketType非IND的工单。排除指标调度(IND)。

### 1.4 核心概念与英文字段业务含义
| 英文字段 | 中文名称 | 业务含义 |
|---------|---------|---------|
| strategyId | 策略编号 | 策略在数据库中的唯一标识，同一策略可能在N条主工单中被引用 |
| isSplit | 是否被拆单 | 子单是否被接收方二次拆分。true=中间子单(不参与全口径覆盖量汇总)；false=叶子子单(参与) |
| targetCustomerCount | 目标客户量 | 子单圈选的待触达客户总量 |
| reachedCustomerCount | 触达客户数 | 实际触达的客户数，仅已完成子单有值 |
| marketingSuccessCount | 营销成功量 | 触达客户中营销成功的客户数 |
| dispatcher | 派单方 | 发出工单的区域，策略分析统计归属的核心依据 |
| ticketType | 工单类型 | STR/CG-OP/COD/GOD/RAS/IND，策略分析排除IND |

### 1.5 指标分类与双轨算法
- **行为量**（策略派发数量、已完成数量）：按**主工单**计数，全口径递归汇总
- **覆盖量**（目标客户量、触达客户数、营销成功量）：按**叶子子单(isSplit=false)**汇总，全口径叶子子单汇总

### 1.6 核心口径规则（10条）
R1~R10，详见Word文档

## 二、逐场景穿越验证

### 场景1：省公司策略直派地市（不拆单）
新疆省公司决定执行策略S1001，创建主工单W1，直接派给乌鲁木齐和克拉玛依，各1个子单直派到位，无拆单。主工单W1=1次策略派发决策。

### 场景2：同一策略被多条主工单复用
策略S1001又在主工单W2中使用，派给阿克苏和喀什。此时S1001在2条主工单中共使用。同一策略被N条主工单使用=策略派发N次，不去重。

### 场景3：省公司策略经地市拆单（一级拆单）
新疆创建主工单W3执行策略S1002，初始拆1个子单S3-1给乌鲁木齐（isSplit=true，已被拆单），乌鲁木齐接收后再拆成S3-2(天山区)和S3-3(沙区)。策略派发数量=1（1条主工单），目标客户量全口径用叶子子单汇总。

### 场景4：非策略调度类型关联策略（客群调度CG-OP）
乌鲁木齐执行客群调度，主工单W4关联策略S1003，派给天山区。ticketType=CG-OP但strategyId非空，纳入策略分析统计。验证"策略跟着工单走"规则。

### 场景5：地市策略经区县二次拆单（二级拆单链）
乌鲁木齐创建主工单W5执行策略S1004，拆1个子单S5-1给天山区（isSplit=true），天山区再拆成S5-2(网格A)和S5-3(网格B)。形成"乌鲁木齐→天山区→网格"的二级拆单链。策略派发数量=1（1条主工单）。

### 场景6：区域攻坚跨级直达网格 + 客户商机调度关联策略
主工单W6(RAS类型)：新疆执行区域攻坚调度，关联策略S1005，跨级直达天山区网格A。主工单W8(COD类型)：乌鲁木齐执行客户商机调度，关联策略S1007，派给沙区，状态待处理。

### 场景7：省公司自执行策略
新疆创建主工单W7执行策略S1006，自己执行不往下派。派单方=接单方=新疆。策略派发数量=1（1条主工单）。

### 场景8：用户举例场景：策略S1001在4条主工单中使用
策略S1001在4条主工单中使用：2条新疆派的（W1给乌鲁木齐、W2给克拉玛依），2条乌鲁木齐派的（W3给天山区、W4给沙区）。每条工单目标1000客户。验证：新疆本级策略派发数量=2，目标=2000；新疆全口径=4，目标=4000；乌鲁木齐本级=2，目标=2000；乌鲁木齐全口径=2，目标=2000。

## 四、与工单分析的口径差异对照
- 行为量统计单元：工单分析=子单，策略分析=主工单
- 视角：工单分析=派单+接单，策略分析=仅派发
- 口径组合：工单分析=8种，策略分析=4种
