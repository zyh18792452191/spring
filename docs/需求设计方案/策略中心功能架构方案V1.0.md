| 图例 | 含义 | 判定口径 | 在原型中的判定依据 |

| 🟧 **橙色（优化）** | 已有页面/能力，但达不到目标形态，需增强 | 页面存在，缺关键字段 / 交互 / 闭环 | 对应《策略中心优化方案 V1.0》第五章 P1～P12 中动作为"改造/拓展"的项 |

> **判定原则**：三色标注只针对**功能能力项**，不针对"页面"；一个页面可能同时包含灰色（保留能力）与橙色（增强能力）部分，例如策略匹配页的"策略编辑"区块为灰、"历史效果参照"区块为蓝。

### 0.2 计数总览（按能力项统计，共 61 项）

| 标注 | 数量 | 占比 | 说明 |
|---|---|---|---|
| 灰色·已实现 | 29 | 47.5% | 策略中心的"底子"已具备，不需要推倒重来 |
| 橙色·已实现待增强 | 15 | 24.6% | 集中在"治理闭环、沉淀闭环、策略要素复用、置信度可解释、端到端可视" |

## 三、L1 策略中心：四大能力域的功能架构

> **定位**（客户原话 + 集团规范共识）：策略中心是**营销活动全流程的集中管理、处理、沉淀**环节——"管理"= 策略治理与配置，"处理"= 定策与出站衔接，"沉淀"= 效果回收与资产化。
> **架构红线（与洞察中心、调度中心的边界）**：① 诊断结论只在洞察中心产生，策略中心只接收受理；② 一个活动只在一个中心留一份明细、一份效果（评估中心算，策略中心只接收）；③ 调度中心负责"谁执行、怎么派"，策略中心负责"做什么、给谁做、用哪套话术产品"。

### 3.1 ① 策略管理（治理层 · 约束所有出站活动）— 9 项能力

| # | 能力项 | 标注 | 现状依据（页面） | 目标形态（本轮要做成什么样） | 数据来源 | 下游消费 | 异常与边界处理 |
|---|---|---|---|---|---|---|---|
| 1 | 与洞察中心对接 | ⬜ 已具备 | `/workspace/strategy/receive-diagnosis` | 保留并补齐"受理 / 批量受理"一键动作 | 洞察中心诊断结论（接口待立项，本期页面导入） | 定策链路第 ① 步 | 接口未通时以页面导入承接，活动实例标记"人工导入" |

### 4.3 工单体系复用关系

策略中心产出的活动，经调度中心落地时复用现有 6 类调度中的**策略调度（STR 前缀）**；商机派单（COD / GOD）、客群调度（CG-OP）、区域攻坚调度（RAS）则复用策略中心配置的策略、话术、产品三元组。**策略中心不新建工单体系**，避免与调度中心重复建设。

## 七、与北京移动《策略中心（1）～（6）》的能力对照与新疆补齐路径

> 集团 / 北京移动的六页规划是**方向正确的标杆**，但它的前置条件（自建智慧大脑、三塔模型、海量样本、合作渠道直连）新疆并不完全具备。因此本方案的做法是：**能力项对齐、实现路径降档**——用规则与人工确认先跑通闭环，用效果数据喂养模型，再逐级升级为 AI 主导。这与图二的"阶段① → ② → ③"完全一致。

| 北京移动规划 | 核心能力 | 新疆现状 | 标注 | 新疆补齐路径（分步） |
|---|---|---|---|---|
| （1）从人工 → 半自动 → AI 的智慧运营演进 | 洞察为源起 → AI 自动生成策略 → 执行 → AI 动态评估 → 复盘沉淀 → 反哺模型 | 洞察侧已具备（AI 指标监控预警 / AI 洞察管理 / 商机体系）；策略生成靠人工；评估已具备策略分析页；沉淀页已具备但引用不通 | 🟧 优化 + 🟦 新增 | 见本方案图二：一期打通"沉淀引用 + AI 复盘"，二期做"AI 辅助定策 + 比选"，三期做"统筹 + 控制"，四期做接口自动回流；阶段③（AI 智能生成 / 实时调整 / 自学习调优）列入规划期 |
| （2）小模型能力升级：从"人-货"匹配升级为"人-货-场"匹配 | 自建智慧大脑推荐模型，覆盖合约到期 / 套包 / 套餐升档 / 全网普惠四类重点产品 | 无自建推荐模型；客群 / 产品 / 渠道在活动配置时由运营人员人工选择 | ⬜ 现状 + 🟦 规划 | **新疆不宜直接对标**（无样本、无产品特征库）。降档路径：① 先用"策略库规则匹配 + 历史效果排序"作为推荐底座（二期）；② 用 3-6 个月的活动效果数据 + 产品/渠道/场景特征，训练轻量匹配模型（规划期）；③ 新增"产品/渠道/场景特征"数据要求，写入活动实例（二期） |

| （4）基于营销目标实现营销资源全局统筹与策略智能生成（三塔模型 + TMM 统筹分配） | 策略智能统筹打分、额度分配、重叠号码按推荐得分排序取最高分、全局最优 | 无统筹能力，多策略并存时靠人工协调 | 🟦 新增 | **先做规则版统筹，再做模型版**：① 规则版（三期）：优先级 + 产能上限 + 同一客户多策略按优先级去重（对齐"同号码取最高分"的业务目标）；② 模型版（规划期）：在具备效果样本后再引入打分模型 |
| （5）基于自然人的策略汇聚与响应式营销矩阵 | 统一接入各子系统触客策略与工单，自然人级清洗汇聚；优先级 TOP1 投诉修复 > TOP2 风险预警 > TOP3 服务关怀 > TOP4 价值营销，避免过度打扰 | 策略控制 / 防打扰能力缺失，仅靠运营人员经验避让 | 🟦 新增 | ① 三期先落地"策略控制（名单 / 频次 / 时段 / 互斥）"，把"避免打扰"变成系统闸门；② 优先级矩阵按新疆实际简化为"投诉/服务类 > 风险预警类 > 价值营销类"三层（三级）；③ 自然人级汇聚（跨 IOP / 网格通 / 商机的统一客户视图）列入规划期，前置依赖四接口立项 |
| （6）GIS 空间策略：地图 + 标签组合，区域级画像洞察与区域级策略输出，沉淀场景化执行清单 | 空间策略统筹、场景化执行清单、场景运营案例沉淀 | 区域攻坚（RAS 调度）已具备地图圈选与小区画像，但"空间策略 → 策略库 → 沉淀案例"链路未打通 | 🟧 优化 + 🟦 新增 | ① 复用现有区域攻坚地图与小区画像能力（已有，不重复建设）；② 把地图圈选的客群结果作为定策第 ② 步的"空间客群"输入（三期）；③ 场景化执行清单沉淀到最佳实践库（三期） |

> **一句话对标结论**：六页规划里"洞察为源起、人工确认、效果反哺"三点新疆**当下就能做**；"自建模型、神经网络统筹、自然人级汇聚"三点**依赖样本与接口，必须等数据积累**。把可做的先做，是新疆版路线与北京版路线的根本差别。

|---|---|---|---|
| 洞察中心 | 客户 / 市场 / 商机 / 产品 / 渠道洞察，输出诊断结论 | 接收诊断接口（诊断结论 → 策略待办） | 诊断只在洞察中心产生，策略中心不造诊断 |
| **策略中心** | 策略治理与配置、定策、活动配置、效果沉淀 | — | 只做"做什么、给谁做、用什么"，不派单、不算效果 |
| 调度中心 | 一线任务与客户任务调度、派单、执行盯控 | 调度接收接口（活动实例 → 调度待办）；执行结果接口（→ 评估） | 派单与执行盯控只在调度中心 |
| 评估中心 | 策略 / 任务 / 人效 / 能力评估 | 评估回流接口（效果数据 → 策略沉淀） | 效果口径只在评估中心定义与计算 |

### 8.2 与商机中心总体规划（前店-中台-后厂）的关系

商机中心规划中的"中台四大能力"（统一精准分级、统一执行盯控、统一诊断评估、AI 智能体）与策略中心是**并列的中台能力**，二者在新疆的实际交汇点是**"策略 × 话术 × 产品"三元组**：

| 交汇点 | 策略中心提供 | 商机体系消费方式 |
|---|---|---|
| 商机派单（COD） | 策略、话术、产品三元组配置 | 派单时按商机分类引用对应策略配置 |
| 客群商机调度（GOD） | 客群级策略与优先级 | 客群商机调度时复用策略与话术 |
| 区域攻坚调度（RAS） | 空间客群与策略（三期打通） | 地图圈选客群后引用策略定策 |

> **结论**：新疆不需要按"商机中心"另建一套策略能力，**策略中心就是全平台唯一的策略出口**，商机 / 客群 / 区域攻坚都从它取策略与话术——这也是图一 L2"输出侧"只画"调度中心 + 评估中心"的原因。

## 九、落地分期与验收（与《策略中心优化方案 V1.0》第七、八章保持一致）

> **分期原则**：① 每一期都必须"可用、可验、可演示"，不做只改样式的半成品；② 依赖跨系统接口的能力一律压到最后一期（接口立项周期不可控）；③ 同一期不出现"改了一个页面又依赖另一个未改造页面"的连环依赖。

### 9.1 四期路线（与图一、图二标注的优先期一致）

| 期次 | 主题 | 交付物（能力项） | 验收标准 |
|---|---|---|---|
| **一期** | 存量打通 + 定策五步链路 | 策略中心总览改造（O-1）；诊断处置补全（M2-2）、历史效果参照（M2-3）、受理/批量受理（M1-1）、风险客群作为定策入参（L0-3）；AI 复盘（M4-3）；模板"应用此模板"（M4-5）；沉淀资产被定策引用（L0-6） | 走通"收到诊断 → 看历史 → 编辑策略 → 提交"全链路，且**每一步都可点、都有真实数据来源**；AI 复盘能输出四大要素（成效结论 / 归因 / 建议 / 模板候选） |
| **二期** | 配置统一 + AI 辅助定策 | 活动配置统一页（M3-4）、活动实例与状态机（M3-5）；策略审批（M1-4）；AI 定策与方案比选（M1-2 / M2-4 / M2-5）；最佳实践评审（M4-6）、关联关系回写（K-2）；批量策略树创建（效率类新增）；置信度与口径展示（B-3）、AI 调用点与降级（B-1） | 三类活动在统一页可配置并生成唯一活动实例；AI 候选方案含置信度与依据，且**人工确认后才出站**；批量建策效率对比单条建策有可量化提升 |
| **三期** | 全局统筹 + 出站控制 | 策略统筹（M1-7）、策略控制（M1-8）、策略-客群匹配规则（M1-9）；空间策略输入（覆盖地图圈选→定策）；权限与操作审计（B-4）；自下而上诉求承接（L0-7） | 同一客户多策略场景下**系统自动去重取最高优先级**并可查看拦截原因；命中控制规则的活动可申诉重放 |
| **四期** | 跨中心接口立项对接 | 接收诊断接口（O-3 / L0-2）、调度接收接口（O-6 / L0-5）、执行结果接口（O-8）、评估回流接口（O-9 / M4-2）；RBAC（依赖集团统一权限平台） | 四个接口全部联通，诊断自动进待办、活动自动进调度、效果自动回流；**移除人工"一键回流"过渡开关** |

### 9.2 依赖与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 四个跨中心接口立项周期不可控 | 自动流转无法按期上线 | 页面侧先就绪（导入 / 一键回流），接口通了只切换数据来源，不改页面结构 |
| AI 能力（聚智平台）可用性与稳定性 | AI 定策 / AI 复盘不可用 | 全部保留降级路径（规则推荐 / 固定模板报表），界面显性提示"AI 未启用"，不静默失败 |
| 效果数据积累不足 | 阶段③（AI 智慧运营）无法验证效果 | 阶段③列入规划期，不以"没有样本"为前提启动；一期即开始沉淀效果数据 |
| 活动口径不统一 | 同一活动两个数字 | 效果口径只在评估中心定义；策略中心只接收与沉淀（写入协作红线） |
| 一线对 AI 结论不信任 | 推荐被忽略、功能空转 | 置信度 + 推荐依据 + 历史参照三者同屏展示；阶段②坚持"人确认" |

### 9.3 本期不做（明确排除，避免误解）

| 不做的事 | 原因 |
|---|---|
| 自建推荐模型 / 三塔模型 / 神经网络统筹 | 无样本、无产品与渠道特征库，先做规则版 |
| 合作渠道（微信 / 支付宝 / 抖音 / 美团）直接投放与回流 | 无直连能力，标注为待建 |
| 自然人级跨系统策略汇聚（跨 IOP / 网格通 / 商机统一客户视图） | 前置依赖四接口立项与统一客户主键 |
| 对话式（大模型对话直接生成策略）创建 | 属规划期能力，本期以表单 + 候选方案形式落地 |
