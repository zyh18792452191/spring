## 〇、文档说明

### 0.1 目的

以"**一条诊断结论 → 一个活动实例 → 一轮效果回流 → 一条可复用资产**"为主线，输出策略中心全流程页面原型 demo 的**实现方案**（改哪些页面、每页字段/交互/数据来源/下游消费）与**实施计划**（按什么顺序做、依赖关系、验收要点），最终演示「洞察 → 定策 → 执行 → 反馈 → 沉淀」五阶段全流程贯通。

### 0.2 三条执行原则

1. **增量优化，不推倒重来**：已上线页面保留并复用，只做增强；仅在能力断点处新建页面。
2. **先打通链路，再做智能化**：先保证"一条诊断结论能走到活动实例、状态全程可追踪"，再叠加"历史效果参照 + 多方案比选 + AI 复盘"。
3. **业务术语为主，代码路径为辅**：功能描述用业务语言，同时标注对应代码文件路径，便于开发落地（本文是实施方案，非 PRD）。

### 0.3 页面动作三类口径

| 动作 | 含义 | 说明 |
|---|---|---|
| **复用** | 保留现有页面，不改造，仅做跳转/数据联动接入 | 不新增开发量 |
| **优化** | 现有页面做增强（加模块、加步骤、加操作、加字段） | 在现有代码上改 |
| **新建** | 当前原型不存在的全新页面 | 新建路由与组件 |

## 二、目标架构与端到端主流程

### 2.1 一句话定位

**策略中心 = 营销活动的运营中枢**：把洞察中心发现的问题转化为可执行的活动方案，交调度中心落地执行、评估中心检验效果，再把效果沉淀为可复用资产反哺下一轮定策。

### 2.2 分层功能架构（demo 落地映射）

| 层 | 职责 | Demo 对应页面 |
|---|---|---|
| 输入侧 | 统一收口（系统预警/人工诊断/客群/商机/一线提报 → 受理） | 接收诊断（受理） |
| 策略管理（治理层） | 策略从哪来、怎么建、谁能上、怎么管、给谁用 | 策略审批（新建） + 策略库/根因库（复用） |
| 策略制定 | 把诊断结论变成可执行方案（五步链路） | 策略匹配页改造（五步） |
| 活动配置 | 方案变活动，输出带全局活动 ID 的活动实例 | 活动配置统一页（新建） |
| 策略沉淀 | 效果入库 → AI 复盘 → 模板与最佳实践 → 沉淀至知识库 | 效果库 + AI 复盘 + 模板管理 |
| 知识中心 | 全流程口径唯一的事实与依据 + 复盘资产复用落点 | 复用（关联关系查询）+ 知识库（复盘结果沉淀） |
| 输出侧 | 做好的活动谁执行、效果谁评估 | 调度中心 / 评估中心（复用）+ 活动全链路追踪（新建） |
| 支撑底座 | AI 智能体 + 数据底座 | 智能体（根因分析/话术生成/AI 复盘）+ 数据底座（指标/客群/渠道/商机） |

### 2.3 端到端主流程（20 步 → 五阶段归纳）

```text
洞察(1-4)        定策(5-11)            执行(12-15)       反馈(16-18)      沉淀(19-20)
指标异常检测      接收/受理诊断         派发配置          输出执行结果      AI 复盘
根因诊断分析   →  历史效果参照      →   工单审批与下发  →  效果评估    →   模板与最佳实践
圈选风险客群      AI 辅助定策          执行监控          效果回流          (反哺定策②③步)
推送诊断结论      方案比选
                 策略编辑
                 活动配置
                 策略审批
```

- **一条主线**：活动实例（全局活动 ID）贯穿四中心，状态：`洞察中 → 制定中 → 调度中 → 执行中 → 评估中 → 沉淀中 → 已闭环`；
- **两个回流**：诊断结论正向流入（洞察→策略）、效果数据反向回流（评估→策略）；
- **一套资产**：历史效果库 + 策略模板库 + 最佳实践库，复盘结果沉淀至知识库复用；
- **策略类型覆盖**：客群类 / 工单类 / 预警类 / 事件类四类策略均走同一全链路闭环。

## 三、Demo 主线演示路径（Golden Path）

演示时走一条完整闭环，验证"链路能跑通、状态看得见、资产能反哺"。演示路径如下：

```text
策略中心总览（生命周期看板，看到在途活动全景）
   ↓ 我的待办 →「待受理诊断」
接收诊断（受理一条诊断结论）
   ↓ 承接
策略制定五步（②历史效果参照 → ③AI 定策与比选 → ④策略编辑）
   ↓ 进入活动配置
活动配置统一页（选活动类型 → 配置 → 生成活动实例，带全局活动 ID）
   ↓ 提交
策略审批（通过）
   ↓ 推送调度（活动实例移交）
活动全链路追踪（看活动走到"执行中/评估中"节点）
   ↓ 评估完成后
策略沉淀·效果库（查看该活动效果记录 → 干预/未干预客群对比 → 点 AI 复盘）
   ↓ 复盘报告（成效结论/归因/模板候选）
策略沉淀·模板管理（复盘生成"模板候选"→ 存为模板）
   ↓ 复盘结果同步沉淀至知识库
   ↓ 下一轮定策
策略制定五步·第②步（历史效果参照出现"相似策略推荐/应用此模板"入口 → 带入定策）
   —— 形成闭环
```

> 以上每一跳都通过页面间带参路由衔接（诊断 ID / 策略 ID / 活动 ID / 模板 ID），demo 用 mock 数据驱动，四中心接口流转用字段预留模拟。

### 4.2 P2 策略制定链路：三步扩为五步（优化）

- **动作**：优化；**代码**：`src/app/workspace/strategy/matching/page.tsx`（路由）+ `src/components/strategy/StrategyMatchingContent.tsx`（核心组件）
- **现状**：`数据洞察 → 策略匹配 → 调度派发`（三步）。
- **目标**：`接收诊断 → 历史效果参照 → AI 定策与比选 → 策略编辑 → 活动配置 → 提交审批`。

| 步骤 | 步骤名 | 载体 | 主要内容 | 动作 |
|---|---|---|---|---|
| ① | 接收诊断 | 接收诊断页（4.3） | 诊断结论列表 + 受理/拒收/转派/忽略 | 已有页面补操作 |
| ② | 历史效果参照 | 策略匹配页新增"步骤 2" | 相似历史策略智能推荐（评估结果支撑）：策略名称、历史使用次数、触达率、办理率、达成率、健康度、来源活动、使用时间；支持策略横向对比 | **新增** |
| ③ | AI 定策与比选 | 策略匹配页新增"步骤 3" | 2-3 个候选方案卡片（方案名、核心动作、客群规模、推荐产品/渠道/话术、预期办理率、置信度）+ 方案比选表 | **新增** |
| ④ | 策略编辑 | 策略匹配页"策略匹配"区（保留） | 根因卡片、AI 改写、AI 补全话术、客群增删、优先级调整、可视化编辑 | 已有 |
| ⑤ | 活动配置 | 活动配置页（4.4） | 选派发系统 → 配置活动明细 → 生成活动实例 | **新增**（跳转） |
| ⑥ | 提交审批 | 策略审批页（4.5） | 提交 → 审批通过 → 推送调度 | **新增独立审批页** |

**关键规则（避免歧义）**：
- 第②步"相似策略"匹配规则：**同业务场景 + 同根因（或根因相似度≥阈值）+ 客群特征重合度≥阈值**，按历史使用次数降序，最多 5 条；相似度与推荐排序依据**评估中心效果评估结果**（达成率、改善幅度、健康度）计算；
- 第②步无匹配结果时，页面明确提示"暂无相似历史策略，可基于根因与知识库直接定策"并引导至第③步，**不允许空白无提示**；
- 第③步候选方案必须**可解释**：每案展示推荐依据（命中的根因、关联策略、历史效果数据），不允许只给结论；候选方案支持**横向对比**（方案名/核心动作/客群规模/推荐产品/渠道/话术/预期办理率/置信度）。

## 七、验收要点

1. **链路贯通**：一条诊断结论能沿"受理→定策→活动配置→审批→追踪→评估→复盘→沉淀至知识库"走通，无断点。
2. **状态可视**：活动实例在总览生命周期看板与全链路追踪视图中的状态一致、可下钻。
3. **资产反哺**：AI 复盘能产出模板候选，模板能"应用"并带回下一轮定策；复盘结果沉淀至知识库复用。
4. **效果评估**：每条策略可自定义观察周期与业务指标，支持干预/未干预客群对比，评估结果支撑相似策略推荐与横向对比。
5. **无重复建设**：活动配置页与策略调度页职责清晰（配置视角 vs 派发视角），共用同一活动实例数据。
