## 一、输入侧：策略从哪里来（7 项）

输入侧的职责是**统一收口**：无论需求来自系统预警、人工诊断、客群清单、商机、外部平台还是一线提报，都汇入策略中心的"接收诊断 / 受理"环节，由人工判断是否承接，避免多头启动活动。

| 编号 | 能力项（现状） | 干什么 | 数据从哪来 | 谁消费、怎么协同 | 异常与边界 |
|---|---|---|---|---|---|
| L0-1 | 指标异常信号（灰） | 指标账期级监控命中阈值时产生预警信号，作为策略需求的触发源之一 | 洞察中心 · AI 指标监控预警 | 流入"接收诊断"受理池，由策略运营判断是否受理、是否需要定策 | 信号 ≠ 必建策略：预警仅入池，受理与否由人裁决，避免预警驱动的盲目活动 |
| L0-2 | 诊断结论（灰 / 接口） | 提供"指标为什么异常"的根因结论，是定策的核心输入 | 洞察中心 · AI 洞察管理（根因分析） | 当前经页面人工导入 / 查看；四期经"接收诊断接口"（O-3）自动推送 | 接口未立项前不阻塞业务：页面受理动作（M2-2）先行承接；诊断结论缺失时不允许直接定策，回到洞察中心补诊断 |
| L0-3 | 风险客群清单（灰） | 提供目标客群，回答"对谁做" | 洞察中心 · 客群标签平台 | 作为定策入参（策略编辑第 ④ 步的客群选择依据）；客群口径以标签字典（K-3）为准 | 客群清单过期或标签口径变更时，以标签字典当前口径为准重新圈选 |
| L0-4 | 商机数据（灰） | 提供客户级商机（含分类 / 来源），作为商机型策略的输入 | 商机池 / 客群商机 / 商机分类模块 | 策略与话术配置复用商机分类维度；商机型调度（COD / GOD）按商机数据派发 | 商机执行状态与策略活动状态分属两套视图，以商机模块自身状态为准，策略侧不回写商机状态 |
| L0-5 | 外部工单与活动需求（灰 / 接口） | 承接 IOP 平台 / 集团一级平台下达的工单与活动需求 | IOP 平台 / 集团一级平台 | IOP 普通营销配置（M3-1）承接配置，纳入统一活动实例（M3-5）；四期经接口自动接入 | 外部需求与本地策略需求在受理池同池排序，不单独开通道 |
| L0-6 | 沉淀资产反哺（橙） | 让历史效果库 / 模板 / 最佳实践在定策时"被看见、被引用" | 策略沉淀域（M4-1 / M4-4 / M4-6） | 打通"效果库 / 模板 → 定策第 ② ③ 步"的引用链路（一期） | 资产被引用仅作参考输入，不自动替人做决策；引用次数作为最佳实践评选依据 |
| L0-7 | 自下而上诉求（蓝） | 承接地市 / 一线的策略需求提报 | 地市 / 一线提报（流程约定） | 与自上而下诊断结论同池排序，进入策略统筹（M1-7）排产 | 本期不建独立页面：先以流程约定 + 人工建活动实例承接，避免为低频场景建重页面 |

**输入侧协同小结**：L0-1～L0-5 五类输入统一收口到接收诊断（M2-1 / M2-2）；L0-6 资产反哺进入定策参照环节；L0-7 走流程约定进入统筹。输入侧本身不做加工，加工全部发生在策略中心四个能力域。

## 二、策略管理域：治理层，约束所有出站活动（9 项）

策略管理域是**治理层**：管"策略从哪来（对接）、怎么建（手动 / AI）、谁能上（审批）、怎么管（版本 / 统筹 / 控制）、给谁用（客群匹配）"，它不直接生产活动，但**所有出站活动都要过它这一关**。

| 编号 | 能力项（现状） | 干什么 | 数据从哪来 | 谁消费、怎么协同 | 异常与边界 |
|---|---|---|---|---|---|
| M1-1 | 与洞察中心对接 · 接收诊断（灰） | 承接洞察中心推送 / 导入的诊断结论，支持受理 / 批量受理 | 输入侧 L0-1 / L0-2 | 策略制定域第 ① 步（M2-1）复用同一受理入口 | 重复推送同一条诊断时按唯一性去重，受理留痕 |
| M1-2 | AI 策略分析并初步制定（橙） | 由"推荐雏形"升级为独立定策环节：给出候选方案 + 置信度 + 推荐依据 | 诊断结论 + 历史效果库 + 根因库 / 关联关系 + AI 底座（B-1） | 策略制定人调优后确认，落入策略编辑（M2-6） | AI 只出候选不出终稿：人工可改可不用；置信度按 B-3 统一展示口径 |
| M1-3 | 手动配置策略（灰） | 绕过 AI 直接新建 / 编辑策略，保障 AI 不可用或低频场景可正常作业 | 策略库编辑页 | 与 AI 定策并行的人工通道，最终同样落入 M2-6 | 手动策略同样过审批（M1-4），无绿色通道 |
| M1-4 | 策略审批（橙） | 由调度页内嵌抽出为**独立审批环节**，审批结论与意见留痕 | 待审策略（定策确认后产生） | 审批岗行使审批；结论回写策略状态（M1-5 版本与上下架） | 审批不通过退回定策人修改，不允许跳过审批直接出站 |
| M1-5 | 策略版本与上下架（灰） | 策略多版本管理与上下架控制，保证执行侧引用的是受控版本 | 策略库 | 调度派发只能选择"在架版本"；版本变更不追溯已生成活动 | 已出站活动继续按出站时版本执行，不受后续版本变更影响 |
| M1-6 | 策略库 7 层结构（灰） | 策略要素的结构化载体：基础信息 → 关联配置 → 适用约束 → 产品 / 方案 → 营销话术 → 渠道适配 → 效果评估 | 策略库管理 | 策略编辑（M2-6）、要素域（E-1～E-9）均落在这 7 层上 | 7 层字段完整性由编辑页校验，缺必填层不允许提交审批 |
| M1-7 | 策略统筹（蓝） | 策略优先级排序 + 产能预估，回答"先做哪条、做多少" | 在途活动实例（数量 / 类型 / 目标区域）+ 渠道产能配置 | 策略主管排产；排序结果作为派发依据，一线诉求（L0-7）同池排序 | 统筹是排序建议而非强制，最终派发仍由人确认；产能数据缺失时按渠道近期均值估算并标注 |
| M1-8 | 策略控制（蓝） | 出站闸门：防打扰 / 名单 / 时段 / 互斥 / 抢占五类约束规则 | 名单库（数据底座）+ 在途活动实例 | 所有出站策略出站前过规则校验；渠道优先级（E-8）由它统一约束 | 命中拦截的策略进入待处理队列，人工裁决后放行或废弃；拦截原因全程留痕 |
| M1-9 | 策略-客群匹配规则（蓝） | 把"哪条策略给哪个客群"显性化，并输出冲突清单 | 客群标签 + 策略适用约束（策略库第 ③ 层） | 派发岗执行依据；客群调度（CG-OP）圈选时按规则过滤 | 规则冲突（同一客群命中多条互斥策略）输出冲突清单，由统筹排序决定归属 |

## 三、策略制定域：五步定策链路（7 项）

策略制定域回答"**怎么把一条诊断结论变成可执行方案**"。定策链路由三步扩为五步：① 接收诊断（含处置补全）→ ② 历史效果参照 → ③ AI 定策 + 方案比选 → ④ 策略编辑（含可视化编辑器）。

| 编号 | 能力项（现状） | 干什么 | 数据从哪来 | 谁消费、怎么协同 | 异常与边界 |
|---|---|---|---|---|---|
| M2-1 | ① 接收诊断 · 受理 / 批量受理（灰） | 定策链路起点：对诊断结论逐条或批量受理 | 输入侧 L0-1 / L0-2 | 受理后进入 ①处置 / ②参照 / ③定策 | 未受理的诊断停留在受理池，不产生任何活动 |
| M2-2 | ① 诊断处置补全 · 拒收 / 转派 / 忽略（橙） | 补全受理闭环的三种"不受理"处置动作 | 受理池 | 拒收 / 转派 / 忽略原因必填留痕，供追溯与四期接口字段设计 | 拒收与忽略的区别：拒收 = 认为诊断不成立（退回洞察中心）；忽略 = 成立但本期不做（留档） |
| M2-3 | ② 历史效果参照（蓝） | 定策时展示相似策略的历史达成率 / 健康度，支持一键引用其配置 | 历史效果库（M4-1，回流数据当前为评估侧人工一键回流） | 策略制定人参照，同时作为 M2-4 AI 候选生成的输入之一 | 无相似历史策略时明确提示"无参照"，不允许展示空参照误导决策 |
| M2-4 | ③ AI 定策 · 候选 + 置信度 + 推荐依据（蓝） | 产出 2～3 套候选方案，每套含置信度与推荐依据 | 诊断结论 + 历史效果参照 + 根因库 / 策略库 / 关联关系 + AI 底座 | 策略制定人查看并进入方案比选（M2-5） | 置信度与口径按 B-3 统一展示（含计算口径 Tooltip）；AI 服务不可用时降级为纯人工定策（M1-3） |
| M2-5 | ③ 方案比选（蓝） | 多方案横向对比表（客群规模 / 预期效果 / 要素差异），选定一套进入编辑 | M2-4 候选方案 | 选定方案写入策略编辑（M2-6）；比选结论留痕 | 仅一套候选时跳过比选直接确认，不强制走形式 |
| M2-6 | ④ 策略编辑（灰） | 把选定方案落成策略：客群 / 产品 / 话术 / 优先级等 7 层结构化配置 | 比选结论 + 模板带入（M4-5） | 编辑结果提交审批（M1-4）；是要素域（E-1～E-9）的配置入口 | 7 层必填校验同 M1-6；编辑过程中的草稿不影响在架版本 |
| M2-7 | ④ 可视化编辑器（灰） | 文案与页面的可视化调整，让话术 / 物料所见即所得 | 策略编辑页文案数据 | 话术运营直接改文案并预览效果 | 可视化编辑仅限文案层，不改变策略结构化字段 |

**定策链路协同小结**：链路起点是诊断结论（洞察中心来），中间参照历史效果（评估中心回流），产出经过审批进入活动配置；链路上每个动作（受理 / 拒收 / 比选 / 确认）都留痕，全程"人确认、AI 辅助"。

## 四、活动配置域：三类活动统一出口（5 项）

活动配置域回答"**方案怎么变成活动**"。三类活动（IOP 普通营销 / 剧本营销 / 网格通）各有配置能力，本域负责统一入口与统一产物——**带全局活动 ID 的活动实例**。

| 编号 | 能力项（现状） | 干什么 | 数据从哪来 | 谁消费、怎么协同 | 异常与边界 |
|---|---|---|---|---|---|
| M3-1 | IOP 普通营销配置（灰） | 承接 IOP 类营销活动：条件设置 → 拆分客群 → 提交审批 | 输入侧 L0-5（IOP 需求）+ 策略库 | 配置结果进入活动实例；审批流走 M1-4 | 外部需求字段与本地字段不一致时，以活动实例统一字段（M3-5）为准做映射 |
| M3-2 | 剧本营销配置（灰） | 多波次流程画布：幕 / 节点 / 波次规则编排 | 策略库 + 剧本编排页 | 剧本活动进入活动实例，波次状态随实例状态机流转 | 波次间依赖不闭环（循环依赖）由画布校验拦截 |
| M3-3 | 网格通活动配置（灰） | 网格属地活动：网格范围 / 执行角色 / 任务包 / 时限 | 策略库 + 区域组织树（地市 / 网格） | 网格任务进入活动实例，交调度中心派至网格人员 | 网格范围与区域组织树不一致时以组织树为准重新校验 |
| M3-4 | 活动配置统一页（蓝） | 三类活动一个页面统一配置：公共字段一次配齐，差异字段按类型展开 | 三类活动现有配置项归并 + 活动实例类型字段 | 活动配置岗一次配齐；统一结构写回活动实例，消除三入口口径不一 | 统一页是入口归并，不是能力替换：三类活动的差异化配置能力全部保留 |
| M3-5 | 活动实例 · 全局活动 ID + 状态机（蓝） | 全计划的枢纽：统一字段 + 状态机（洞察中 → 制定中 → 调度中 → 执行中 → 评估中 → 沉淀中 → 已闭环） | 定策确认动作 + 活动配置结果 | 调度派单携带活动 ID；评估回流按活动 ID 对账；总览看板按状态统计 | 状态只能由各环节动作驱动流转，不允许手工改状态；活动 ID 一经生成不变更 |

**活动配置协同小结**：活动实例是策略中心对下游的**唯一交付物**——调度中心拿"实例 + 三要素"执行，评估中心拿"实例 ID"对账，总览看板拿"实例状态"展示，四个中心因它而串成一条主线。

## 五、策略沉淀域：资产反哺（6 项）

策略沉淀域回答"**活动做完留下什么**"：效果入库 → AI 复盘 → 模板与最佳实践，形成反哺下一次定策的资产闭环。

| 编号 | 能力项（现状） | 干什么 | 数据从哪来 | 谁消费、怎么协同 | 异常与边界 |
|---|---|---|---|---|---|

## 六、策略要素域：产品 / 方案、话术、渠道（9 项）

### 6.1 要素域定位：决定"卖什么、怎么说、在哪说"

策略要素域是策略库 7 层结构中的第 ④⑤⑥ 层（推荐产品 / 方案、营销话术、渠道适配）的**能力化视图**。它回答三个问题：

- **产品 / 方案（E-1～E-3）——决定"卖什么"**；

### 6.5 要素域与周边的协同关系

## 十、一条主线：活动实例贯穿四个中心

### 10.1 状态机

活动实例（全局活动 ID）按以下状态流转，**每个状态由对应环节的动作驱动**，不允许手工改状态：

```
洞察中 → 制定中 → 调度中 → 执行中 → 评估中 → 沉淀中 → 已闭环
```

| 状态 | 由谁驱动进入 | 关键动作 |
|---|---|---|
| 洞察中 | 洞察中心 | 诊断结论生成 / 指标预警触发 |
| 制定中 | 策略中心 · 定策链路 | 受理（M2-1）→ 参照 / AI 定策 / 比选（M2-3～M2-5）→ 策略编辑（M2-6）→ 审批通过（M1-4） |
| 调度中 | 调度中心 | 出站提交（O-5）→ 派发（O-4，携带活动 ID 与三要素） |
| 执行中 | 执行侧 | 触点执行 / 网格作业，执行明细回传 |
| 评估中 | 评估中心 | 执行结果回传（O-8）→ 策略分析（O-7）出效果结论 |
| 沉淀中 | 策略中心 · 沉淀域 | 效果回流（O-9 / M4-2）→ AI 复盘（M4-3）→ 模板 / 最佳实践沉淀 |
| 已闭环 | 沉淀完成 | 全链路归档，活动 ID 终态 |

### 10.2 全局活动 ID 在各环节的用法

- **调度派单**携带活动 ID，执行明细按 ID 归集；
- **评估对账**按活动 ID 匹配"目标值 vs 实际值"；
- **效果回流**按活动 ID 写回历史效果库，对不上的记录进待核对队列；
- **全链路追踪（新增）**：以活动 ID 为主线的时间轴视图，任一活动在四个中心的每个节点可查。

### 10.3 两个回流

| 回流 | 路径 | 当前形态 | 目标形态 |
|---|---|---|---|
| 正向流入 | 洞察中心诊断结论 → 策略中心受理池 | 页面人工导入（不阻塞业务） | O-3 接口自动推送（四期） |
| 反向回流 | 评估中心效果结论 → 策略沉淀（效果库 / 置信度） | 人工一键回流（M4-2） | O-9 接口自动入库并驱动置信度校准（四期） |
