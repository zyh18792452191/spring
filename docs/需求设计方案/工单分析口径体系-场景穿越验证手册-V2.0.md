# 工单分析口径体系——场景穿越验证手册 V2.0

> **V2.0 核心变更**：覆盖量指标（目标客户数/触达客户数/营销成功量）的全口径算法从"递归汇总"改为"叶子子单汇总"，解决多级拆单链路中同一批客户被重复计数的问题。行为量指标（派单量/待处理/已处理/撤单）的全口径算法保持"递归汇总"不变。

---

## 一、口径体系总览

### 1.1 三维度交叉定义

工单分析口径体系由三个维度交叉产生 8 种口径组合：

| 维度一：视角 | 维度二：范围 | 维度三：时间 | 口径名称 | 示例 |
|------------|------------|------------|---------|------|
| 派单 | 本级 | 当月 | 派单-本级-当月 | 新疆6月本级派发了多少单 |
| 派单 | 本级 | 累计 | 派单-本级-累计 | 新疆1~6月本级累计派发了多少单 |
| 派单 | 全口径 | 当月 | 派单-全口径-当月 | 新疆6月含下级共派发了多少单 |
| 派单 | 全口径 | 累计 | 派单-全口径-累计 | 新疆1~6月含下级共派发了多少单 |
| 接单 | 本级 | 当月 | 接单-本级-当月 | 乌鲁木齐6月本级接收执行了多少单 |
| 接单 | 本级 | 累计 | 接单-本级-累计 | 乌鲁木齐1~6月本级累计接收执行了多少单 |
| 接单 | 全口径 | 当月 | 接单-全口径-当月 | 乌鲁木齐6月含下级共接收执行了多少单 |
| 接单 | 全口径 | 累计 | 接单-全口径-累计 | 乌鲁木齐1~6月含下级共接收执行了多少单 |

### 1.2 组织架构树（全场景共用）

```
新疆（L1，根节点）
├── 乌鲁木齐（L2，地市）
│   ├── 天山区（L3，区县）
│   │   ├── 网格A（L4，叶子节点）
│   │   └── 网格B（L4，叶子节点）
│   └── 沙区（L3，区县）
│       └── 网格C（L4，叶子节点）
└── 克拉玛依（L2，地市）
    └── 独山子区（L3，区县）
        └── 网格D（L4，叶子节点）
```

统计月份：2026-06

### 1.3 指标分类与全口径算法（V2.0 核心变更）

工单分析的指标按业务本质分为两类，两类指标在全口径下使用不同的汇总算法：

| 指标类型 | 代表指标 | 业务含义 | 全口径算法 | 原因 |
|---------|---------|---------|----------|------|
| **行为量** | 派单量、接单量、待处理、已处理、撤单 | 统计的是"动作次数" | **递归汇总**：本区域+所有下级区域的子单数量之和 | 每次派发都是独立行为，1拆5就是5次，不重复 |
| **覆盖量** | 目标客户数、触达客户数、营销成功量 | 统计的是"真实的人" | **叶子子单汇总**：仅汇总未被二次拆单的叶子子单的覆盖量之和 | 同一批客户被多级拆单时只算1次，递归汇总会重复计数 |

**反面示例（V1.0的bug）**：

新疆派800人给乌鲁木齐，乌鲁木齐拆成500+300给天山区和沙区。

- 行为量（递归汇总）：新疆全口径派单量=1+2=3 ✓（3次独立派发行为）
- 覆盖量（递归汇总，旧算法）：新疆全口径目标客户=800+500+300=1600 ✗（同一批客户被重复计数）
- 覆盖量（叶子子单汇总，新算法）：新疆全口径目标客户=500+300=800 ✓（同一批客户只算1次）

### 1.4 拆单链与叶子子单定义

拆单是指接单方收到子单后，将子单进一步拆分为多张子子单派发给更下级区域。拆单形成链路：

| 子单类型 | 定义 | 是否参与覆盖量全口径汇总 |
|---------|------|----------------------|
| 根子单 | 由主单直接派发的子单（parentSubTicketId=null） | 若被拆（isSplit=true）则不参与；若未被拆（isSplit=false）则参与 |
| 中间子单 | 被接单方二次拆单的子单（isSplit=true） | **不参与**——其覆盖量数据已由其叶子子单代表 |
| 叶子子单 | 未被二次拆单的子单（isSplit=false） | **参与**——代表真正执行到底的客户覆盖 |

示例：

```
S6-1: 新疆→乌鲁木齐(800人, isSplit=true)
├── S6-2: 乌鲁木齐→天山区(500人, isSplit=true)
│   ├── S6-4: 天山区→网格A(300人, isSplit=false ✓叶子)
│   └── S6-5: 天山区→网格B(200人, isSplit=false ✓叶子)
└── S6-3: 乌鲁木齐→沙区(300人, isSplit=false ✓叶子)

全口径目标客户数 = 叶子子单汇总 = 300+200+300 = 800
递归汇总（旧算法）= 800+500+300+300+200 = 2100 ← 重复计数，错误
```

### 1.5 核心口径规则清单

| 编号 | 规则 | 详细说明 |
|------|------|---------|
| R1 | 全口径递归至最末级 | 行为量：全口径=本级+直接下级全口径（递归至网格级）；覆盖量：全口径=本区域+所有下级区域内叶子子单的覆盖量之和 |
| R2 | 年初累计 | 累计值=1月至当月的月度值之和，跨年清零重置 |
| R3 | 当月归集 | 当月口径仅统计派发时间/接收时间在当月的子单，不含历史月份创建但跨月完成的数据 |
| R4 | 二次派单不算已处理 | 每级只算直属一级子单；二次拆单后，原始子单的派单方视为"已处理"但不算终端执行完毕，只有末端网格执行完毕才算 |
| R5 | 撤单规则 | 撤单的子单：派单视角照计派单量（派发动作已发生），但不计入待处理量和已处理量；接单视角不计入接单量、待处理量、已处理量 |
| R6 | 派单视角看派发行为 | 某区域"派单"指该区域作为派单方发出的子单，与该区域是否在组织树上无关 |
| R7 | 接单视角看执行责任 | 某区域"接单"指该区域作为接单方接收的子单，全口径递归时按组织树汇总 |
| R8 | 覆盖量去重（V2.0新增） | 覆盖量指标全口径仅汇总叶子子单（isSplit=false），避免拆单链上中间子单的同一批客户被重复计数 |
