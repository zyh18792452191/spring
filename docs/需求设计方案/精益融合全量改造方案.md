##### 1.1.3.2 右侧规则可视化画布

**核心设计理念**：预警规则采用**可视化逻辑编排**，支持"并集（OR）+ 交集（AND）"的组合逻辑。

**画布结构**：

```
请输入预警名称                    [+ 添加并集]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
并集分支1（#）:
  ┌─────────────────────────────────────────┐
  │ 规则1: 离网概率 > 1   [修改][删除][添加] │
  │          且（□）                          │
  │ 规则2: 是否手机或宽带状态异常 是  [修改][删除][添加] │
  └─────────────────────────────────────────┘
并集分支2（#）:
  ┌─────────────────────────────────────────┐
  │ 规则1: 概率排名 > 1   [修改][删除][添加] │
  │          且（□）                          │
  │ 规则2: 是否投诉用户 是  [修改][删除][添加] │
  └─────────────────────────────────────────┘
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
*更新周期: ●实时触发
```

**逻辑关系说明**：

| 符号 | 含义 | 说明 |
|------|------|------|
| # | 并集（OR） | 不同分支之间为"或"关系，任一分支满足即触发预警 |
| □ | 交集（AND） | 同一分支内的规则为"且"关系，全部满足才认为该分支匹配 |

**规则卡片操作**：

| 按钮 | 功能 |
|------|------|
| 修改 | 修改当前规则的参数（如阈值、比较运算符） |
| 删除 | 从当前分支中移除该规则 |
| 添加 | 在当前规则下方添加一条新规则（与当前规则为"且"关系） |

**添加并集**：在画布中新增一个独立的并集分支。

**更新周期**：

| 选项 | 说明 |
|------|------|
| 实时触发 | 数据变更时即时检查规则 |
| （其他选项推测） | 日更/周更/月更等周期性检查 |

### 1.3 差异分析

#### 1.3.1 核心差异总览

| 维度 | 精益融合平台（目标态） | 当前系统（现状态） | 差距等级 |
|------|---------------------|------------------|---------|
| **预警类型** | 5种（任务类/保有类/提醒类/效果类/到期类），按业务场景分类 | 4级（红/橙/黄/蓝），按严重程度分级 | 🔴 **概念级差异**：类型≠等级，两者维度不同 |
| **业务场景关联** | 业务专题→业务场景→客户类型 三级联动 | 关联指标组 单级选择 | 🔴 **缺失**：无业务场景体系 |
| **规则编排** | 可视化画布，支持并集分支+交集组合 | 平铺列表，仅支持线性且/或 | 🔴 **架构级差异**：逻辑表达能力不在一个量级 |
| **规则来源** | 左侧规则选择栏（预置规则库+标签分类） | 指标下拉选择（仅4个指标） | 🔴 **缺失**：无规则库 |
| **执行周期** | 开始日期+结束日期（范围） | 单个生效日期（时点） | 🟡 **部分缺失**：缺周期结束时间 |
| **工单信息** | 完整：执行模式(4种)+执行角色(5种)+工单名称+备注 | **无** | 🔴 **完全缺失** |
| **工单执行预览** | 16地州×执行模式×执行角色 表格 | **无** | 🔴 **完全缺失** |
| **操作流程** | 取消/保存(草稿)/提交(审批) 三态 | 确认/取消 两态 | 🟡 **部分缺失**：缺草稿和审批流程 |
| **预警场景主题** | 有，文本输入 | 无 | 🟡 **缺失** |
| **更新周期** | 实时触发 | 无 | 🟡 **缺失** |
| **预警名称长度限制** | 有（20字+计数器） | 无长度限制 | ⚪ 细节差异 |

#### 1.3.2 关键差距深度分析

##### 差距1：预警类型 vs 预警等级（概念错位）

**现状问题**：当前系统的"预警等级"（红/橙/黄/蓝）和精益融合的"预警类型"（任务类/保有类/提醒类/效果类/到期类）是**两个完全不同维度的概念**：

- **预警等级**：描述预警的严重程度，是预警触发后的属性
- **预警类型**：描述预警的业务分类，是预警创建时的定义

**改造方向**：两者应该**并存**而非替代。预警类型用于分类和筛选，预警等级用于优先级排序和展示。

##### 差距2：业务场景体系（缺失）

**现状问题**：当前系统仅有"关联指标组"（3个选项），没有业务场景体系。

**精益融合的设计逻辑**：
```
业务专题（存量运营/增量运营/流量运营/家庭运营/国际业务）
  └→ 业务场景（与业务专题联动，如"存量运营"→"宽带存量客户关怀"）
      └→ 客户类型（全球通客户/动感地带/神州行等）
```

这是三级联动选择，上层选择决定下层选项范围。

**改造方向**：需要建立完整的业务场景体系字典，包含三级数据。

##### 差距3：规则可视化编排（架构级差异）

**现状问题**：当前系统的规则编辑是平铺的行列表，每行=指标+运算符+阈值，规则之间仅通过"且/或"线性连接。

**精益融合的规则编排**：

```
分支1（OR）:
  规则A: 离网概率 > 1         ←  AND
  规则B: 是否手机或宽带状态异常 是

分支2（OR）:
  规则C: 概率排名 > 1          ←  AND
  规则D: 是否投诉用户 是
```

等价逻辑表达式：`(A AND B) OR (C AND D)`

这种"并集分支内含交集组合"的表达能力，远超当前的线性且/或。

**改造方向**：需要重新设计规则编排UI，从平铺列表升级为可视化画布，支持：
1. 左侧规则选择栏（规则库+搜索+标签分类）
2. 右侧规则画布（并集分支+交集组合+可视化逻辑线）
3. 规则卡片（修改/删除/添加操作）
4. 添加并集按钮

##### 差距4：工单信息与执行预览（完全缺失）

**现状问题**：当前预警规则配置完全没有工单相关内容。

**精益融合的设计逻辑**：
- 预警触发后需要生成工单并分配执行
- 执行模式决定工单的执行方式（分包看管/在线/混合/自定义）
- 执行角色决定谁来执行（10086/网格经理/10088/政企客户经理/地市集运）
- 工单执行预览让用户在提交前确认各地州的执行配置

**改造方向**：需要新增两个完整模块：
1. **工单信息**：执行模式+执行角色+工单名称+备注
2. **工单执行预览**：16地州×执行模式×执行角色表格，支持按地州差异化配置

##### 差距5：规则库（缺失）

**现状问题**：当前系统的预警指标仅有4个（离网客户数/ARPU/DOU/MOU），远不够业务使用。

**精益融合的规则库**（从截图可见至少12条）：
- 布尔判断类：是否合约到期、是否手机或宽带状态异常、是否投诉用户、是否漫出用户、是否老旧套餐、是否竞对干扰、是否过度办理、是否突然零次、是否合约到期原因
- 数值比较类：离网概率、是否ARPU增长>=25%
- 排名比较类：概率排名

**改造方向**：需要建立预警规则库，支持：
1. 规则定义（名称/类型/参数/标签）
2. 标签分类管理
3. 搜索筛选
4. 动态扩展（新增规则不需要改代码）

#### 4.2.6 预警规则状态流转

```
草稿 ──→ 保存（继续编辑）
  └──→ 提交审批 ──→ 待审批 ──→ 三级领导审批通过 ──→ 已生效
                                    └──→ 审批驳回 ──→ 已驳回（发单人修改后重新提交）
已生效 ──→ 停用
停用 ──→ 启用（重新生效）
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| 草稿 | 保存未提交 | 编辑、删除、提交审批 |
| 待审批 | 已提交等待三级领导审批 | 撤回（发单人）、审批通过/驳回（三级领导） |
| 已驳回 | 三级领导驳回 | 编辑、重新提交审批、删除 |
| 已生效 | 审批通过，系统按周期扫描执行 | 停用 |
| 停用 | 暂停扫描和工单生成 | 启用 |

### 4.3 审批流程

#### 4.3.1 审批机制

**三级领导是一个职位（分管领导），不是一个节点序列**。审批只有一个节点：

```
配置人提交 → 三级领导审批（一个节点）→ 通过：预警生效
                                → 驳回：发单人修改后重新提交
```

**演示简化**：同一个人既是发单人也是三级领导（审批人），方便演示审批流转。

### 4.4 预警工单生成与跟踪

#### 4.4.1 生成机制

预警规则审批通过→已生效后，系统按更新周期扫描数据：

```
更新周期触发
  → 扫描数据（大数据平台/CRM系统）
    → 匹配预警规则条件
      → 命中客户列表（号码级）
        → 每个号码生成一条子工单
          → 关联流程执行
            → 网关判断客户属性（是否全球通/是否白金卡/是否宽带）
              → 走对应分支
                → 外部节点推送（指挥调度/短信平台等）
                  → 外系统执行
                    → 状态回传
                      → 本系统更新工单状态
```

**关键约束**：预警工单**不在"工单处理"中生成待办**，因为实际执行在外系统，本系统只做跟踪。
