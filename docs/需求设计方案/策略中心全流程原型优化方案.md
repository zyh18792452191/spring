# 策略中心全流程原型优化方案

> 版本：V1.0
> 依据：《策略中心全流程操作手册》端到端演示路径实测反馈（附件 `assets/Untitled.docx`）
> 关联文档：`docs/需求设计方案/策略中心全流程页面原型Demo实现方案与计划.md`

## 一、概述

本方案针对用户按《策略中心全流程操作手册》实际走通「洞察 → 策略制定 → 调度 → 评估（策略分析）→ 沉淀」端到端演示路径后，反馈的问题与建议进行逐项收敛与优化设计。

优化目标：**让演示路径可闭环、交互有响应、内容不空壳、跨中心有衔接**，最终达到"每一步操作都有可观察的反馈、每个页面都有经得起推敲的内容"。

问题类型归类：

| 类型 | 说明 | 对应问题 |
|------|------|---------|
| 交互缺失 | 按钮/链接已展示但未绑定点击逻辑，点击无任何反馈 | P2、P8 |
| 内容缺失 | Tab 内容为空壳或未迁入已有内容 | P4、P5 |
| 信息缺失 | 展示字段不完整，无法支撑判断 | P3 |
| 流程关联缺失 | 跨中心/跨步骤之间缺少衔接入口 | P1、P6、P7 |

## 二、问题清单（对照端到端演示路径）

| # | 环节 | 问题现象 | 根因 | 类型 |
|---|---|---|---|---|
| P1 | 洞察 → 接收诊断 | 诊断结论未流转到接收诊断 | 洞察中心与策略中心无联动入口/数据贯通 | 流程关联缺失 |
| P2 | 策略匹配 | 「引用」「采用此方案」「比选」「方案ABC切换」均无反应 | 新增按钮为静态展示，未绑定 onClick | 交互缺失 |
| P3 | 策略匹配 | 「一降到底规模」缺指标ID、指标描述、原因 | 指标信息展示字段不完整 | 信息缺失 |
| P4 | 活动配置 | 三 Tab 切换无反应；剧本/多波次内容空壳 | 三 Tab 共用同一表单，仅场景库变；未迁入已有内容 | 内容缺失 |
| P5 | 活动配置 | 网格通未纳入统一页 | 网格通仍独立在外 | 功能缺失 |
| P6 | 策略审批 | 「我发起」无「发起调度」入口 | 审批后未提供调度衔接 | 流程关联缺失 |

## 三、优化方案（逐项）

### P1 洞察 → 接收诊断流转

**问题现象**：洞察中心的诊断结论（如指标异动诊断）未自动/手动流转到策略中心的「接收诊断」，导致"洞察 → 定策"链路断裂。

**根因分析**：洞察中心与策略中心之间缺少数据贯通入口，诊断结论停留在洞察侧，无法成为定策的输入。

**优化方案**：
1. **接收诊断页新增「手动接收」入口**：模拟洞察中心推送，一键将洞察诊断结论带入待处理诊断列表，形成"待处理 → 待承接"的贯通。
2. **洞察总览增加「推送诊断」动作**：在洞察诊断结论处提供推送动作，将诊断（含指标、异常原因、影响区域）写入接收诊断。
3. **关联 AI 指标监控预警**：预警管理中触发预警的规则，其预警结论可作为自动诊断来源，自动进入接收诊断（demo 阶段以模拟数据呈现联动关系）。

**验收标准**：从洞察侧发起推送（或接收诊断侧手动接收）后，接收诊断列表出现对应诊断记录，且可继续走「承接 → 策略匹配」流程。

### P2 策略匹配交互补齐

**问题现象**：「历史效果参照」中「引用」按钮、「AI 定策与比选」中「采用此方案」「比选」按钮、方案 ABC 切换均无任何点击反馈。

**根因分析**：该区块为静态展示，按钮未绑定 onClick，方案切换未绑定选中态。

**优化方案**：
1. 「引用」→ 将该历史策略的要素（产品/方案、话术、渠道）回填到④策略编辑区。
2. 「采用此方案」→ 选中对应方案并高亮，回填要素进入策略编辑。
3. 「比选」→ 展开方案对比表（方案/置信度/预期转化/要素对比）。
4. 「方案 ABC 切换」→ 绑定选中态，点击切换高亮与右侧要素预览。

**验收标准**：四个交互点均有点击反馈，且能影响后续策略编辑内容。

### P3 指标信息补全

**问题现象**：策略制定区「当前分析指标：一降到底规模」仅显示指标名称，缺少指标 ID、指标描述、异常原因，无法支撑"为什么定这个策略"的判断。

**根因分析**：指标信息展示字段不完整。

**优化方案**：分析指标区增加三字段展示：
- 指标 ID（如 `IND-DECLINE-001`）；
- 指标描述（该指标的统计口径与业务含义）；
- 异常原因（AI 诊断给出的根因结论）。

**验收标准**：指标区完整展示名称 + ID + 描述 + 原因四要素，且与诊断来源数据一致。

### P4 + P5 活动配置 Tab 重构

**问题现象**：
- IOP 普通营销 / 剧本营销 / 多波次营销三个 Tab 切换无实质内容变化（共用同一表单，仅场景库变化）；
- 剧本营销、多波次营销内容为空壳，未迁入已有内容；
- 网格通活动配置仍独立在外，未纳入统一页。

**根因分析**：三 Tab 共用同一 `TabsContent`，视觉无差异；已有剧本营销/多波次营销/网格通内容未迁入。

**优化方案**：
1. **三 Tab 各自独立内容**：
   - IOP 普通营销：IOP 触点活动配置（渠道/话术/触点）；
   - 剧本营销：迁入已有剧本编排内容（场景剧本/话术编排）；
   - 多波次营销：迁入波次计划内容（波次节奏/触点排布）。
2. **新增第 4 个 Tab「网格通」**：统一迁入网格通活动配置内容。

**验收标准**：切换四个 Tab，内容均有实质差异；剧本/多波次/网格通内容完整呈现。

### P6 策略审批·发起调度

**问题现象**：审批通过后，「我发起的」Tab 中无法直接发起调度，需自行前往调度中心。

**根因分析**：审批环节与调度环节缺少衔接入口。

**优化方案**：「我发起的」Tab 中，对已通过的活动实例增加「发起调度」按钮，点击跳转调度中心（携带活动 ID，回填调度表单）。

**验收标准**：已通过活动实例可一键跳转调度中心并发起调度。

### P7 调度总览/策略调度

**问题现象**：
- 策略调度弹窗中策略内容无法点击查看；
- 首次策略制定（无历史效果、无比选）缺少「新增策略」入口；
- 客群调度未关联活动配置。

**根因分析**：弹窗内无交互、无新增入口、无活动关联。

**优化方案**：
1. 策略调度弹窗内策略内容可点击查看详情；
2. 首次策略（无历史效果/比选）提供「新增策略」入口，跳转策略编辑；
3. 客群调度弹窗增加「关联活动配置」字段。

**验收标准**：策略内容可点开；首次策略可新增；客群调度可关联活动。

### P8 评估中心执行记录

**问题现象**：策略分析页点击「执行记录」无反应。

**根因分析**：执行记录按钮未绑定交互。

**优化方案**：执行记录按钮补交互，点击展开执行明细（触达 → 转化漏斗 + 各节点状态）。

**验收标准**：点击执行记录能展开执行明细，可查看漏斗与节点状态。

## 四、实施顺序

```
P3(信息补全) + P2(交互补齐)          → 优先修复直接影响演示的交互与信息问题
P4 + P5(活动配置 Tab 重构)            → 消除空壳，统一四 Tab
P6 + P7 + P8(流程/交互衔接)           → 补齐跨中心衔接与弹窗交互
P1(洞察流转)                          → 打通洞察 → 定策入口
```

优先级原则：**先修"看得见的无反应"，再补"看不见的衔接"**——优先保证演示路径上每一步操作都有反馈，再做跨中心的数据贯通。
