一、策略中心在运营中心中的能力定位
1.1 一句话定位
策略中心是运营中心的"策略运营中枢"——营销活动全流程的集中管理、处理、沉淀。它把洞察中心发现的问题转化为可执行的活动方案，交调度中心落地执行、评估中心检验效果，再把效果沉淀为可复用资产反哺下一轮定策，是唯一贯穿洞察 → 调度 → 评估三个中心的主线。
承接局方核心意见：剧本营销只是策略中心的一个功能点；策略中心应基于实际使用场景覆盖营销活动全流程——含 AI 分析历史策略、结果沉淀、定策时参照历史策略效果数据——拥有"洞察 → 策略 → 调度 → 评估 → 效果回流 → 策略沉淀"的端到端视角。对齐集团规范：策略中心承担策略创建、AI 策略推荐、策略统筹（优先级排序）、策略控制（防打扰 / 名单 / 时段 / 互斥）、策略产能预估等能力。

策略管理三层展开（2026-09-15 增补）：上表中策略中心「通过洞察中心相关输入整合输出策略方案」的环节，扩展为策略管理，包含三层——①洞察对接层：与洞察中心对接，接收诊断结论、风险客群、根因标签、场景类型、指标数据等结构化输入（见 3.2 节），作为策略分析的数据基础；②AI 策略分析层：AI 接入洞察中心数据，进行 AI 策略分析并初步制定策略（2-3 个候选方案 + 置信度），供人工比选、采纳或修订；③手动配置层：支持人工直接配置策略（策略内容、客群、渠道、优先级等），不依赖 AI 推荐，与 AI 初拟结果并行编辑、互为补充。三层之上沿用审批、版本、启停、策略-客群匹配规则与策略控制等治理动作。
策略管理产出的策略，其后由调度中心在各运营场景中使用（落地场景见 3.3 节），执行与转化结果经评估中心策略执行分析回流（见 3.4 节），最终进入策略沉淀（策略中心新增功能模块，体系设计见第四章）——形成「策略管理 → 场景使用 → 执行分析 → 策略沉淀」的完整闭环。

- 洞察中心只诊断不开方：输出结构化诊断信息，不指定策略方案。
- 策略中心只管方案与配置，不管派发："建议执行渠道"仅供参考，最终派发由调度中心规则引擎决定；活动实例推送后进入监控状态。
- 调度中心只管执行不管好坏：输出工单与执行状态，不判断效果是否达标。
- 评估中心只评估不改策：输出效果数据与建议，不直接修改策略；策略修改由策略中心在下一轮定策时参照执行。
- 知识库只存关联不存效果：根因-策略关联强度由策略中心回写，效果明细存策略中心历史效果库。

- 回流起点在策略调度页：是否开启后评估开关 + 月指标后评估周期，随活动实例下发；不开后评估则该策略没有回流链路。
- 评估中心总览：区域筛选（全疆 / 地州 / 多选）→ 工单改善情况（派发 / 完成 / 达成率 / 同比）→ 区域评估（地图 + 各区域健康度）→ 策略评估摘要（派发量 / 完成率 / 触达率 / 成功率 / AI 采纳率五指标，健康度绿 / 黄 / 红）。
- 跨中心协作-评估页：「订阅告警」按策略 ID + 阈值订阅，健康度异常实时推送。
- 效果库页：评估回流自动入库，无需人工操作；页面提供策略分类 + 业务场景 + 时间范围 + 评估健康度四维筛选。

7.8 数据流转的边界与回流点
- 派发即移交：策略调度页「提交派发」后，策略中心进入监控状态，只在跨中心协作-调度页查看与撤销 / 补发，不再干预派发规则（对应 3.6 节红线二）。
- 回流全自动：效果数据经评估回流接口自动进入效果库并触发 AI 复盘，页面上无手工录入动作；策略侧页面只做查询、筛选与审核。
- 反哺靠按钮：闭环的最后一步是显式页面动作——模板管理页「应用此模板」把客群 / 渠道 / 产品 / 话术建议带入策略匹配页，最佳实践在定策时优先展示。

7.9.1 市场运营：指标调度 / 策略调度 / 客群调度
流量运营页（/portal/traffic-operations）市场总览按业务场景组织指标卡片，「去调度」打开调度弹窗：指标调度弹窗填写区域选择、指标目标值、是否开启后评估、紧急程度；客群调度弹窗配置月指标后评估周期。确认后进入流量运营调度页（/portal/traffic-operations/dispatch），表单分 8 个分区：基础信息（业务场景 / 工单类型 / 标题 / 要求完成时间 / 工单描述 / 紧急程度）、小区标签、客户筛选标签、触客策略、已选小区列表、评估指标、派单信息、审批信息；工单类型枚举覆盖 IND / STR / CG-OP / COD / GOD / RAS。策略中心产出的策略在「触客策略」「客户筛选标签」分区被引用，随工单进入调度执行。
7.9.2 我的工作台：商机派单预制策略
客户商机页（/workspace/business-opportunity/customer）以待派单状态优先排序，支持单条与批量派单：选择派发系统（网格通 / 在线）、执行角色、推荐产品；批量派单按网格自动拆分子工单。增补能力：派单时预制策略——由策略中心基于洞察数据与策略沉淀库提供话术推荐 / 策略推荐候选，随子工单一并下发，执行人无需临时编写话术。
7.9.3 我的工作台：预警规则配置预制策略
预警规则管理页（/workspace/business-opportunity/warning-rules）现有 WT001 待处理商机积压、WT002 商机逾期两类预警，维度规则含统计维度（省 / 市 / 区 / 网格 / 执行人员）、级别（高 / 中 / 低）、阈值参数、持续时长、检查频率、告警方式、接收人、启用开关。增补能力：配置预警规则时同步预制触发后的处理策略（话术推荐 / 策略推荐），预警触发即自动带出预制策略，形成「预警 → 预制策略 → 派单处理」的联动。
三类场景的策略均来自策略中心策略管理（3.1 节）的产出，执行转化结果进入评估中心策略执行分析（3.4 节），最终回流策略沉淀（第四章）。

8.2 整体能力收口
策略中心的能力可以用"一条操作主线、一份数据载体、两个回流、一套资产"收口：
- 一条操作主线：接收诊断页 → 策略匹配页 → 策略调度页 → 评估中心总览 → 策略沉淀页，即原型三步进度条"数据洞察 → 策略匹配 → 调度派发"向两端的自然延伸；用户全程只在这五类页面上操作。
- 一份数据载体：活动实例（活动 ID + 配置 JSON，原型结构 DispatchOrder）是唯一贯穿四中心的数据对象，客群、渠道、优先级、后评估配置全部随单流转。
- 两个回流：诊断结论经接收诊断页正向流入；效果数据经效果库反向回流并自动触发 AI 复盘。
- 一套资产：历史效果库 + 策略模板库 + 最佳实践库，通过「应用此模板」与优先推荐两个页面动作反哺下一轮定策。
由此，策略中心在运营中心中的完整能力是：承接洞察诊断，参照历史效果，经策略管理（洞察对接 / AI 策略分析 / 手动配置）产出可执行方案，统一配置三类活动并治理出站，移交调度中心在市场运营三类调度与商机派单 / 预警规则预制策略场景中使用，回收评估中心策略执行分析结果并沉淀为可复用资产——每一轮定策都站在上一轮效果数据之上，形成越用越准的策略运营中枢。
