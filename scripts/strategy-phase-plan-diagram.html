阶段一 · 链路补齐
把"有资产、没链路"补成端到端可跑
目标：一条诊断结论能从受理走到活动实例，全程有状态、可追踪。
策略中心总览改造统计仪表盘 → 活动生命周期看板 + 我的待办 + 健康度 + 资产概览
定策链路：历史效果参照定策时可见相似策略的历史达成率 / 健康度
定策链路：AI 定策 + 方案比选产出 2-3 套候选方案（含置信度与推荐依据）并横向比选
接收诊断受理动作补全补拒收 / 转派 / 忽略，形成完整受理闭环
活动实例与全局活动 ID统一字段 + 状态机（洞察中→…→已闭环），供调度与评估消费
沉淀资产被引用"应用此模板"一键带入定策第③步，并累计引用次数
AI 复盘成效结论 / 关键归因 / 改进建议 / 模板候选
策略要素随活动下发产品 / 方案、话术、渠道三要素与活动实例绑定（现基线）
完成标志

一条诊断结论可从受理走到活动实例，活动状态全程可追踪；主管可在看板看到全部在途活动。

前置依赖：无（本阶段为起点）
阶段二 · 资产复用与比选
让沉淀资产真正参与定策，AI 稳定介入定策
目标：定策不再"凭经验手写"，而是"看历史效果 + 比多方案 + 复用要素"。
活动配置统一页IOP 普通营销 / 剧本营销 / 网格通三类活动一个页面统一配置
策略审批独立页从调度页内嵌抽出为独立审批环节，审批留痕
AI 定策升级候选方案 + 置信度 + 推荐依据，支持人工调优后确认
最佳实践评审闭环入选标准 + 候选 → 评审 → 发布 → 归档
关联关系回写AI 复盘回写关联强度与置信度（关联关系查询自动更新）
产品 / 方案要素模板化高频产品组合沉淀为要素模板，一键复用到新策略
AI 话术生成按客群 / 场景生成话术，人工确认后入话术库
话术 A/B 与版本对比同一策略多条话术并行投放，按转化率择优沉淀
置信度展示与口径说明AI 结论统一展示置信度 + 计算口径 Tooltip
完成标志

定策时可看到历史效果并完成多方案比选；模板、话术要素可复用且有引用与转化数据。

前置依赖：阶段一的定策链路与活动实例（无实例则无法计引用与转化）
阶段三 · 统筹与管控
多策略并行不打架，口径与权限可控
目标：多条策略同时上线时，优先级、产能、频次、触点冲突由规则统一约束。
策略统筹策略优先级排序 + 产能预估，决定"先做哪条、做多少"
策略控制防打扰 / 名单 / 时段 / 互斥 / 抢占，约束所有出站策略
策略-客群匹配规则哪条策略给哪个客群显性化，作为派发依据
空间策略输入区域 / 网格维度的策略输入，支撑属地攻坚
要素与产品库口径联动产品编码 / 优惠口径与产品运营统一，避免二次维护
渠道优先级与频次统一约束渠道优先级由策略控制统一约束，不与调度侧重复配置
触点协同规则多触点互斥 / 接力 / 优先规则，交调度中心按规则选触点
权限与操作审计页面级权限 + 审批 / 复核岗位区分，操作留痕
自下而上诉求承接地市 / 一线提报按约定流程进入策略需求池
完成标志

多条策略并行时冲突可被规则自动约束；产品 / 话术 / 渠道要素全平台口径唯一；审批与操作可审计。

前置依赖：阶段二的活动实例与要素模板（控制与统筹需以实例为单位生效）
阶段四 · 跨中心接口立项
用接口替代人工搬运，闭环自动化
目标：策略与洞察 / 调度 / 评估三中心之间的数据流转由接口自动完成。
接收诊断接口洞察中心 → 策略中心：诊断结论自动推送，无需人工导入
调度接收接口策略中心 → 调度中心：活动实例自动进入调度待办
执行结果接口调度中心 → 评估中心：执行结果自动回传
评估回流接口评估中心 → 策略中心：效果数据自动回流至效果库
效果回流接收升级由"人工一键回流"升级为接口自动入库，并驱动根因 / 策略置信度更新
完成标志

四个接口联调通过：诊断可自动进策略、活动可自动进调度、结果自动进评估、效果自动回策略沉淀。

前置依赖：阶段一～三的页面侧流程已跑通（接口只是把人工动作自动化）；接口立项与联调依赖上游系统配合
阶段划分与图例说明：阶段顺序＝能力依赖顺序，不设时间轴（不给出起止时间与工期）。灰底＝本阶段沿用的已实现基线；橙底＝已实现但需增强；蓝底＝未实现、本轮新建；白底虚框＝未实现、需跨系统接口立项。完成标志＝该阶段验收锚点，同时是下一阶段的前置依赖；未通过验收即进入下一阶段会形成返工。四个阶段与《策略中心优化方案 V1.0》第七、八章的分期、验收口径一致；逐项能力清单（含现状依据）见《策略中心功能架构方案 V1.0》第六章。
为什么接口放在最后：接口的作用是把已经跑通的人工动作自动化。若页面侧流程未固化（阶段一～三），接口落地后仍需反复改字段与状态定义，返工成本高于先跑通人工闭环。因此四个跨中心接口统一放到阶段四立项对接，与本平台"页面侧先就绪、接口后立项"的既有做法一致。
