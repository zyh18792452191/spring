输入侧：策略从哪里来

指标异常信号（洞察中心 · AI 指标监控预警）、诊断结论（洞察中心 · AI 洞察管理 / 根因分析）、风险客群清单（客群标签平台）、商机数据（商机池 / 客群商机）四类输入统一收口到策略中心，由「策略管理」的接收诊断环节承接；外部工单与活动需求（IOP 平台 / 集团一级平台）作为外部来源，沉淀资产（效果库 / 模板 / 最佳实践）与一线自下而上诉求作为补充输入。协同方式：前三类走「接收诊断接口」（本期以页面受理承接），外部需求走导入与人工受理。

策略中心：每块干什么

策略管理＝治理层，管版本、审批、控制（防打扰 / 名单 / 时段 / 互斥）与统筹排序，约束所有出站活动；策略制定＝把诊断结论变成可执行方案，五步链路（接收诊断 → 历史效果参照 → AI 定策 → 方案比选 → 策略编辑）；策略要素＝把方案落到产品 / 话术 / 渠道三要素，随活动一起下发；活动配置＝三类活动（IOP 普通营销 / 剧本营销 / 网格通）的统一出口，产出带全局活动 ID 的活动实例；策略沉淀＝效果回流 → 复盘 → 模板与最佳实践，反哺下一次定策；知识底座＝根因库 / 关联关系 / 标签字典 / 市场事件，为全流程提供口径与依据。

输出侧与底座：怎么和周边协同

活动实例以统一活动 ID 输出到调度中心（五类调度派发、触点按渠道适配与协同规则执行）；执行结果进入评估中心（策略分析 14 项执行指标、区域钻取、本级 / 全口径对比）；再由评估回流把效果写回策略沉淀与根因 / 策略置信度。接收诊断、调度接收、执行结果、评估回流四个跨系统接口是打通三个中心的关键，页面侧已就绪、依赖接口立项。底座由 AI 大模型与智能体（根因分析 / 策略生成 / 话术生成 / AI 复盘，能力来自聚智平台）、数据底座（标签库 / 指标库 / 指标字典）、置信度与口径说明、权限与操作审计共同支撑。

颜色判定口径（已实现 / 未实现）：灰底＝已实现，原型中路由存在且能力可点通（代码级核实）；橙底＝已实现但需增强，页面已存在、缺关键字段 / 交互 / 闭环；蓝底＝未实现，本轮新建；白底虚框＝未实现，页面侧已就绪、依赖跨系统接口立项。 阶段实现计划：四期建设内容见《策略中心阶段实现计划图》，分期与《策略中心优化方案 V1.0》第七、八章一致，逐项明细见《策略中心功能架构方案 V1.0》第六章能力清单（含现状依据）。
